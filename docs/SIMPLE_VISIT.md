# A simpler visit

The owner asked for one small workflow: review a work order, ask questions, arrive onsite, add findings, report back and receive a final update. Photos help when available; they are not a prerequisite.

The main screen now follows four stages:

1. **Work order.** Read the problem and assigned work. Ask about the job. Access, customer and source details are available when needed.
2. **On site.** Add findings or ask a question. The new fictional assignment includes an Operations-supplied gate code with its own source revision. Existing saved assignments are not silently changed.
3. **Report back.** Speak or type what happened. Review spoken words before Send. A saved local voice note is not a sent answer. The connection status appears above the conversation; an unavailable live service cannot silently start the local recorder.
4. **Final update.** Read the saved testimony and the separate repair, production, monitoring and warranty follow-ups. Review the name, notes and owners, then confirm. Operations acceptance remains separate.

Moving between stages does not verify arrival or field work. Work-order questions use bounded source lookup; this is not general model reasoning or web retrieval. Missing details remain unavailable, and equipment procedures still require an applicable approved source. Questions do not become technician testimony. The existing guarded Meta interpretation and explicit photo-selection paths remain in place. Typed testimony saves locally; it does not automatically run an interpretation. Live reviewed Send retains its existing guarded text-review path.

The optional saved-notes controls and developer simulator are collapsed below the visit. The native toolbar has only the app name, connection details and reconnect. No separate participant photo webpage is needed for this test.
