# A simple field conversation

The main screen shows the customer, clickable phone/address details when supplied, the current reply and **Hold to speak**. Hold while talking; release to get an answer. There is no separate Start live demo, transcript approval or Send step in this conversation. Sources, optional photos, saved recordings, typing and handoff review stay under Details.

The technician can ask for the work-order brief, ask about the gate, describe onsite findings, correct a detail and ask for the final update. Work-order questions use the supplied source notes and do not become field testimony. Ordinary visit reports use guarded Meta interpretation to propose one useful follow-up. Final update is a draft: speaking does not confirm a report, deliver it or establish Operations acceptance.

Hold release explicitly submits the utterance. Automatic machine words remain marked unreviewed and linked to the original WAV/hash. Corrections preserve earlier words. The main flow never sends old recordings or photo bytes implicitly. Photo review remains a separate selection. Imported customer contacts carry a source ID/revision; older work orders without a phone do not gain an invented number. The fresh sample has fictional contact details.

## Connection and microphone

The installed iPhone development app remembers its existing private HTTPS credential in the device Keychain. Startup and explicit Reconnect renew only authentication, never replay field work or inference. The credential is not in Git, the app bundle or web JavaScript. Browser access retains its gate. System TLS verification and the configured private origin remain required.

For that trusted main frame, native build 8 reuses an already granted iOS microphone permission instead of asking for WebKit origin permission on every hold. First iOS permission remains required. Camera requests still prompt. Capture starts only on a hold and does not restart after interruption.
